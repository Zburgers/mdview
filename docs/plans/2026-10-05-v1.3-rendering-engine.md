# mdview v1.3 Rendering Engine Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use shipyard:shipyard-executing-plans to implement this plan task-by-task.

**Goal:** Replace mdview's ad-hoc preview pipeline with a structured, security-preserving rendering subsystem and ship stable heading/Outline navigation, local Markdown links, resilient local images, rich Mermaid/chart rendering, syntax-highlighted code, expanded callouts, highlights, footnotes, bounded math, tables, and reader polish.

**Architecture:** Keep Marked + DOMPurify + KaTeX + Mermaid, but move them behind a per-render `src/rendering/` contract that returns safe HTML plus heading/resource/diagnostic metadata. Render once for the active document, feed the same `RenderResult` to Preview and Outline, and keep filesystem authorization in Rust/Tauri. Preview enhancers may add behavior after sanitization, but they must not widen the document trust boundary.

**Tech Stack:** Tauri v2, Rust, React 19, TypeScript 5.9, Vite 7, Marked 16.4.x, DOMPurify 3.x, Mermaid 11.x, KaTeX 0.18.9, Highlight.js 11.12.x, Vitest/jsdom.

## Non-negotiable invariants

1. Markdown remains untrusted input.
2. Marked output is never inserted into the webview without mdview sanitization.
3. Mermaid stays `securityLevel: "strict"` and generated SVG is sanitized.
4. Remote images remain blocked by default.
5. External HTTP/HTTPS links still require explicit native confirmation.
6. Local filesystem paths are authorized by Rust before use in the webview.
7. Document-supplied `file:`, `asset:`, `tauri:`, `javascript:`, and unsupported schemes remain blocked.
8. One bad image/diagram/math/code block must not blank unrelated content.
9. The active document is parsed once per Markdown/render-policy change; opening the Outline or changing the search query must not reparse it.
10. No graph view, backlinks, workspace indexing, global search, transclusion, plugin API, or arbitrary trusted HTML enters this release.
11. Existing v1.2.5 behavior for task toggles, wikilinks, tab dirty-state safety, save safety, and release safety must not regress.
12. Any sanitizer allowlist expansion requires a focused security regression test in the same commit.

## Dependency decisions

### Add

- `highlight.js@11.12.x`
  - Import `highlight.js/lib/common` or explicit core languages, never the all-language top-level bundle.
  - Reason: syntax highlighting with controlled bundle growth and no framework dependency.

- `marked-footnote@1.4.0` only after its output passes the sanitizer/accessibility spike in Task 10.
  - If it is incompatible with the pinned Marked line or requires unsafe HTML, stop Task 10 and implement the smallest equivalent Marked extension locally; document the divergence before continuing.

### Keep pinned for this release

- Marked 16.4.x
- Mermaid 11.x (current lockfile resolves 11.15.0)
- KaTeX 0.18.9
- DOMPurify 3.x

Do not combine a Marked or Mermaid major-version upgrade with this renderer refactor.

## Target render contract

```ts
export type HeadingEntry = {
  id: string;
  text: string;
  level: 1 | 2 | 3 | 4 | 5 | 6;
  ordinal: number;
};

export type RenderResource = {
  kind: "image" | "local-link" | "remote-link";
  raw: string;
};

export type RenderDiagnostic = {
  level: "info" | "warning" | "error";
  code: string;
  message: string;
};

export type RenderResult = {
  html: string;
  headings: HeadingEntry[];
  resources: RenderResource[];
  diagnostics: RenderDiagnostic[];
};

export type RenderOptions = {
  allowRemoteImages: boolean;
  theme: "light" | "dark";
};
```

Theme may ultimately stay out of the pure Markdown compiler if only Mermaid requires it. If so, keep `theme` in Preview enhancement options rather than forcing it into the parser.

## Shipyard cold-review checklist

Before implementation is declared ready for maintainer review, re-read this plan and the actual branch from disk/repository and answer:

- Does one active Markdown change cause one parse?
- Can Outline/search/theme UI accidentally trigger duplicate parsing?
- Are heading IDs deterministic with duplicates and Unicode?
- Are local link clicks user-action-only?
- Can a local link or image bypass Rust authorization?
- Can `../` image resolution become an absolute/document-supplied privileged URI?
- Can remote-image behavior regress to implicit network access?
- Does any new Marked extension inject elements/attributes absent from sanitizer tests?
- Can Highlight.js output bypass DOMPurify?
- Can KaTeX expansion/size be abused without bounds?
- Can Mermaid source or generated SVG make a network request while remote resources are disabled?
- Does any diagram failure blank unrelated document content?
- Does any new component depend on global `document.getElementById` for active-note navigation?
- Did we accidentally implement workspace/backlink/graph/global-search scope?
- Did dependency imports materially worsen the existing bundle warning?
- Are all release/version operations still untouched?

Any **Critical** or **Major** answer/finding blocks merge.
