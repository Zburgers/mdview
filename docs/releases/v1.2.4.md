# mdview v1.2.4 — Release Notes

> Validation date: 2026-08-28. The `1.2.4` branch is release-ready; public publication remains gated by the immutable tag workflow.

mdview `1.2.4` is a focused privacy, reliability, rendering, and desktop-stability release. It strengthens how local preferences are persisted, prevents untrusted Markdown from silently loading remote resources, ensures external links leave the application only after native confirmation, fixes a Marked inline-token crash, and improves frameless-window interaction, tabs, updater correctness, and settings scrolling.

## Highlights

### Rendering and updater correctness

- Fixed the Marked `codespan` rendering crash by allowing Marked to render nested inline link tokens through its supported renderer path.
- The installed version is read from native Tauri metadata, then compared with updater metadata using semantic-version ordering. Equal and older remote versions are ignored; only a valid newer version can install and relaunch.
- Release validation now requires matching package, Cargo, Tauri, tag, changelog, and updater-manifest versions, and tagged workflows validate before any platform bundle can publish.

### Frameless desktop stability

- Added native Tauri edge and corner resize hit targets for the undecorated window, while preserving the configured minimum dimensions.
- Simplified title-bar drag/maximize handling to avoid competing drag mechanisms implicated in repeated maximize/restore blackout reports.
- Redesigned document tabs into compact editor tabs with quiet inactive states, clear active accents, dirty indicators, accessible semantics, close actions, and horizontal overflow.
- Made the settings drawer internally scrollable so Updates and App Info remain reachable at the minimum window size without leaking document scroll.

### Safer Markdown previews

Remote images embedded in Markdown or raw HTML are blocked by default. Local relative images, mdview-generated local asset URLs, blob URLs, and supported raster image data URLs continue to work.

The protection now covers the complete rendering pipeline:

- Markdown image syntax
- raw HTML image elements
- protocol-relative URLs
- unsupported, local-file, and document-supplied Tauri asset URI schemes
- SVG and non-image data URLs
- Mermaid source containing external resources
- remote references in generated Mermaid SVG

Users who deliberately need externally hosted images can enable **Remote Images** in Settings.

### Native confirmation for external links

Rendered Markdown can no longer navigate the mdview webview directly.

HTTP and HTTPS links now:

1. open a native confirmation dialog
2. remain closed when confirmation is declined
3. open in the operating system's default browser through the Tauri opener when approved
4. show a native error dialog if the browser cannot be launched

Local file links and unsupported protocols are blocked with a native explanation instead of failing silently or navigating inside the application. Primary clicks, middle clicks, and link context-menu paths are contained by the same policy.

### Crash-safer settings persistence

Settings are now written through a temporary file and atomically replaced after the data is flushed. mdview also keeps a last-known-good backup and preserves malformed files for diagnosis and recovery.

This protects locally stored preferences including:

- theme
- view mode
- recent files
- synchronized scrolling
- preview security preferences

A startup ordering fix also prevents default frontend state from overwriting persisted preferences before the saved settings finish loading.

### Better desktop scrolling behavior

The application shell and workspace no longer become unintended page-level scroll containers. Scrolling remains scoped to the source and preview panes, keeping the title bar, toolbar, tabs, and status area stable while reading long documents.

The workspace no longer applies transforms that can interfere with text rendering or fixed desktop layout behavior.

## Added

- A **Remote Images** preference, disabled by default.
- Native confirmation before opening external HTTP or HTTPS links.
- Native error and blocked-link dialogs for failed or disallowed navigation.
- Mermaid source preflight for external resource references.
- Remote-resource filtering for generated Mermaid SVG.
- Atomic settings writes with a temporary file, flush, backup, and replacement flow.
- Corrupt settings preservation using uniquely named `.corrupt` files.
- Backup recovery when the primary settings file cannot be parsed.
- Regression coverage for the Markdown and Mermaid resource sandbox.
- A documented Markdown rendering threat model and allowlist.

## Changed

- Remote image loading is now opt-in rather than automatic.
- Protocol-relative remote images are normalized to HTTPS only when remote images are enabled.
- Rendered links are intercepted before the webview can navigate.
- Local and unsupported link schemes are rejected explicitly.
- Mermaid SVG receives a dedicated sanitization and resource-policy pass.
- Settings are loaded before frontend persistence begins.
- Desktop overflow is constrained to document panes rather than the entire webview.

## Fixed

- Fixed a Marked `codespan` token crash when valid nested inline content appears in links.
- Fixed updater/version ambiguity by using native installed metadata and rejecting equal, older, malformed, or failed update paths safely.
- Fixed release publication ambiguity with immutable tag/ref checks and a pre-bundle validation gate.
- Fixed repeated frameless title-bar drag/maximize handling that could leave a blackout region after maximize/restore cycles.
- Fixed settings drawer content being clipped below the viewport.
- Replaced the raised browser-style document tabs with compact editor tabs.
- Fixed privacy issue #4, where opening a Markdown file could automatically request a remote tracking image.
- Fixed reliability issue #5, where an interrupted settings write could truncate `settings.json` and silently reset user preferences.
- Fixed the initial default-settings save racing with asynchronous settings loading.
- Fixed Mermaid as a potential bypass around ordinary Markdown remote-image filtering.
- Fixed external links being able to fall through to embedded webview navigation paths.
- Fixed long documents causing the application shell or page to scroll instead of the intended editor and reader panes.

## Security model

The preview continues to support GitHub-flavored Markdown, tables, task lists, code blocks, details/summary elements, local images, and Mermaid diagrams. Scripts, frames, forms, media elements, embedded objects, arbitrary styling, raw SVG, document-supplied privileged asset URLs, and unsupported navigation schemes remain blocked.

The detailed policy is documented in [`docs/security/markdown-rendering-sandbox.md`](../security/markdown-rendering-sandbox.md).

## Upgrade notes

No settings migration is required. Existing settings files remain compatible because missing fields receive safe defaults.

Remote images that previously loaded automatically will display without a source until **Remote Images** is enabled. This behavior is intentional.

## Suggested GitHub Release summary

mdview `1.2.4` hardens the local Markdown preview and settings layer while polishing the desktop shell. Remote images are blocked by default across Markdown, raw HTML, and Mermaid; external links require native confirmation before opening in the system browser; Marked nested inline rendering no longer crashes on valid codespans; settings writes are atomic with backup recovery; release metadata is validated end to end; and compact tabs, native frameless resizing, stable maximize/restore handling, and an internally scrolling settings drawer keep the workspace usable.
